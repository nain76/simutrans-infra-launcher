# サーバー側でやること

友人のランチャーは、インターネット越しに3種類のファイルを取りに来ます。1つ目はサーバーリスト（`list-ランダムな文字.json`、以前の版で作った場合は`manifest.json`）で、サーバー名や接続先、paksetの情報が書いてあります。2つ目はサーバーリストの署名（`list-ランダムな文字.sig.json`）で、管理者が公開したものだと確かめるために使います。署名はスクリプトが自動で作ります。3つ目はpaksetのファイルと、そのファイル一覧（`index.json`）です。

これらのファイルは、アドレス（URL）で取れる場所に置く必要があります。ここでは、simutransサーバーを動かしているWindows Serverに、Windows標準のWebサーバー機能（IIS）を足して置く方法を説明します。IISはフォルダの中のファイルをそのまま配るだけで、プログラムは動かしません。

## 全体像

```
Windows Server
├─ C:\simutrans-server\              ← simutrans サーバー本体（今までどおり）
│    ├─ simutrans.exe
│    └─ pak128.japan\                ← サーバーが使う pakset。アドオンはここに入れる
│
└─ C:\simutrans-dist\                ← IIS でポート 8080 番で公開するフォルダ（構築ツールが作る）
     ├─ list-7k3qf9x2m4.json         ← サーバーリスト（名前の後ろはランダム。構築ツールが作る）
     ├─ list-7k3qf9x2m4.sig.json     ← サーバーリストの署名（公開のたびに自動で作る）
     ├─ engine\                      ← simutrans 本体（版ごとのフォルダ。Publish-Engine.ps1 が作る）
     └─ pak128.japan-x8f2k9qa\       ← pakset（名前の後ろはランダム。Publish-Pakset.ps1 が作る）
          ├─ index.json
          ├─ web.config
          └─ （pakset のファイル）
```

友人がランチャーに入れるアドレスは`https://<サーバーのドメイン>:8443/<サーバーリストの名前>`です（例は`https://example.ddns.net:8443/list-7k3qf9x2m4.json`）。HTTPSにしない場合は`http://<サーバーのドメイン>:8080/<サーバーリストの名前>`になります。サーバーリストの名前は、推測されにくいように後ろにランダムな文字を付けます（「名前を推測されにくくする」の節を参照）。あわせて、確認コード（`A1B2-C3D4-E5F6-0718-293A`のような文字列）を友人に一度だけ伝えます。確認コードについては「署名と確認コード」の節で説明します。

## 最初に1回だけやること

構築はツールが自動で行います。手順は次のとおりです。

1. この`server-setup`フォルダを、Windows Serverの好きな場所にコピーする
2. `Setup-Server.bat`をダブルクリックし、「このアプリがデバイスに変更を加えることを許可しますか？」で「はい」を押す
3. ツールの質問に答える
4. 「HTTPSにしますか？」と聞かれたらYと答える
5. 最後に表示される「残りの作業」を行う

質問されるのは、ランチャーに表示するサーバー名、友人が接続に使うドメイン（例は`example.ddns.net`）、simutransサーバーのポートです。ポートは起動時の`-server`に付ける番号で、1台目なら13353です。最後に、simutransサーバーが使っているpaksetフォルダのフルパス（例は`C:\simutrans-server\pak128.japan`）を聞かれます。エクスプローラーでフォルダをShiftを押しながら右クリックし、「パスのコピー」を選ぶと貼り付けられます。

HTTPSにすると、無料の証明書を取ります。そのためには、80番のポートに外から届くようにしておく必要があります。

残りの作業は4つです。まず、外からTCP 80と8443とsimutransサーバーのポートに届くようにします（「ポートを外から届くようにする」の節を参照）。次に、自分のPCのブラウザで`http://<ドメイン>:8080/manifest.json`が開けるか確かめます。外から届くかを確かめるため、サーバー自身ではなく自分のPCで開いてください。それから、友人にアドレスと確認コードを伝えます。友人はランチャーの「追加」から「サーバー管理者から共有されたリストを追加」を選んでアドレスを入れ、続けて確認コードを入力します。最後に、署名の鍵のバックアップを作っていなければ、`Manage-SigningKey.bat`で作ってVPSの外に保管します。

### 構築ツールがすること

構築ツール（`Install-DistServer.ps1`）は何度実行しても同じ状態になります。途中で失敗したら、もう一度実行してください。

ツールはまずIISを入れます。再起動が必要と言われたら、再起動してからもう一度実行してください。次に、公開フォルダ`C:\simutrans-dist`を作ってポート8080で公開し、Windowsファイアウォールでポート8080とsimutransサーバーのポートを開けます。フォルダの中身の一覧表示はオフにします。

公開フォルダには、読み出し（GETとHEAD）以外の要求を断る設定を入れます。そのため、友人を含めて外の誰もファイルを書き換えたり消したりできません。

サーバーリストがなければ作って1台目を登録し、paksetとsimutrans本体を公開します。すでにあればそのまま使い、登録済みのpaksetを公開し直します。答えた内容は`publish-settings.json`に残るので、次からは`Publish-Pakset.bat`だけで公開し直せます。

そのあと、サーバーリストに署名します。署名の鍵がなければ作って確認コードを表示し、最初の1回だけバックアップを作るかを聞きます。最後に、サーバーリストを取得できることと、書き込み要求が断られることを確かめ、HTTPSにするかを聞きます。HTTPSの設定は`Enable-Https.ps1`が行います。

以前にpaksetの名前だけを答えて構築した場合も、もう一度`Setup-Server.bat`を実行してフルパスを答えれば公開されます。サーバーリストはそのまま使います。

### 引数で指定する

質問に答える代わりに、引数で指定することもできます。PowerShellを管理者として開いて実行してください。

```powershell
Set-ExecutionPolicy -Scope Process Bypass
.\Install-DistServer.ps1 -PublicHost example.ddns.net -ServerName "友達内輪鯖A" `
    -PaksetSource C:\simutrans-server\pak128.japan
```

| 引数 | 既定値 | 説明 |
|---|---|---|
| `-Port` | `8080` | 配信に使うポート |
| `-DistDir` | `C:\simutrans-dist` | 公開フォルダ |
| `-PublicHost` | （質問する） | 友人が接続に使うドメイン |
| `-ServerName` | （質問する） | ランチャーに表示するサーバー名 |
| `-ServerId` | （自動） | サーバーリストに書くサーバーのid |
| `-GamePort` | （質問する） | simutransサーバーのポート |
| `-PaksetSource` | （質問する） | simutransサーバーが使っているpaksetフォルダのフルパス |
| `-HttpsPort` | `8443` | HTTPSのポート |
| `-SkipHttps` | なし | HTTPSにしない（署名があるので本体も配れるが、通信は暗号化されない） |
| `-Email` | なし | Let's Encryptからの連絡先。省略すると、win-acmeが英語で「Enter email(s)」と聞いてくる |

### ポートを外から届くようにする

使うポートは次のとおりです。Windowsのファイアウォールはツールが開けます。

| ポート | 使いみち |
|---|---|
| TCP 8443 | HTTPSでの配信（友人のランチャーがここを見る） |
| TCP 80 | 無料証明書の取得と更新の確認（Let's Encryptがアクセスする）。開けたままにする |
| TCP 8080 | HTTPでの配信（HTTPSにしない場合） |
| simutransサーバーのポート | ゲームの接続（例: 13353） |

そのほかに必要な設定は、サーバーの置き場所で変わります。simutransのポートを開けたのと同じ場所に足すと考えてください。

| 置き場所 | やること |
|---|---|
| VPS | 事業者の管理画面に、サーバーの手前のファイアウォールがあれば、上のポートを許可する（ConoHaの「セキュリティグループ」、さくらのVPSやXserver VPSの「パケットフィルター」など）。その仕組みがなければ何もしなくてよい。VPSにはルーターがないので、ポート転送は要らない |
| 自宅など、ルーターの内側 | ルーターの「ポート転送」（「ポートマッピング」「静的IPマスカレード」とも呼ぶ）で、上のポートをこのサーバーへ転送する |

## simutransサーバーを増やすとき

`Add-Server.bat`をダブルクリックし、サーバー名とポートとpaksetフォルダのフルパスに答えます。ツールは、サーバーリストへの追加、paksetの公開、Windowsファイアウォールでのポートの開放まで行います。

```
C:\simutrans-dist\                 ← 8080 番で公開（増やしても1つのまま）
 ├─ list-7k3qf9x2m4.json          ← サーバーリスト。全サーバー分が入る
 ├─ pak128.japan-x8f2k9qa\        ← サーバーA が使う pakset
 └─ pak128.japan-2-m3c7v2pd\      ← サーバーB が使う pakset（中身が違う）
```

サーバーを増やしても、友人が登録するアドレスは1つのままです。ランチャーの一覧に、全サーバーが並びます。ポートを分けるのはsimutransサーバーだけで（例は13354）、配信用の8081番などを増やす必要はありません。VPS事業者のパケットフィルターなどがある場合は、そこでも新しいsimutransサーバーのポートを許可してください。

同じpaksetフォルダを使うサーバーを足した場合は、公開済みのpaksetを共有します。中身の違うpaksetが同じフォルダ名（例はどちらも`pak128.japan`）の場合は、公開用に`pak128.japan-2`のような別の名前を自動で付けます。友人のPCでも別のフォルダに入るので、サーバーを切り替えても落とし直しにはなりません。接続のときに照らし合わせるのは中身のチェックサムで、フォルダ名ではないためです。

### paksetを公開し直す

`Publish-Pakset.bat`をダブルクリックすると、登録したすべてのpaksetを公開し直します。変わっていないものはすぐに終わります。別の設定で公開したいときは、PowerShellで引数を指定して実行します。

```powershell
.\Publish-Pakset.ps1 `
    -Source      C:\simutrans-server\pak128.japan `
    -Destination C:\simutrans-dist\pak128.japan `
    -Manifest    C:\simutrans-dist\list-7k3qf9x2m4.json `
    -ServerId    friends-a
```

スクリプトの実行が止められた場合は、先に`Set-ExecutionPolicy -Scope Process Bypass`を実行してください。そのPowerShellの画面の中だけ、実行を許可します。

## サーバー管理ツール

`Simutrans_ServerManager.exe`をこの`server-setup`フォルダに置いてダブルクリックすると、サーバー管理の画面が開きます。管理者として動くので、「変更を許可しますか？」には「はい」を押してください。

まだ構築していないときは、画面の上に「新規構築を始める」のボタンが出ます。押すと`Setup-Server.bat`が開くので、質問に答えて構築してください。

画面の上には、公開アドレス、確認コード、署名の状態が並びます。署名が正しければ緑の札が出ます。「配信を確かめる」を押すと、友人のランチャーと同じ方法で公開アドレスからサーバーリストを取り、署名を確かめます。

画面の中ほどでは、サーバーごとに表示名とお知らせを書き換え、メンテナンス中の表示を切り替えられます。「保存して署名」を押すと、`Edit-ServerList.ps1`がサーバーリストを書き換えて署名し直します。

画面の下の「作業」には、これまでのバッチファイルを呼ぶボタンが並びます。押すとPowerShellの画面が開き、バッチファイルをダブルクリックしたときと同じように動きます。終わったら「読み込み直す」を押してください。サーバー管理ツールは書き換えをすべてスクリプトに任せているので、バッチファイルを直接使い続けてもかまいません。

## 名前を推測されにくくする

`manifest.json`のような決まった名前だと、ドメインとポートを知っている人に、サーバーリストの中身を見つけられやすくなります。そのため、新しく構築するときは、サーバーリストを`list-ランダムな文字.json`という名前で作り、paksetの公開フォルダの名前にもランダムな文字を付けます。友人のPCでのpaksetのフォルダ名は変わりません。

以前の版で構築した`manifest.json`は、そのまま動き続けます。推測されにくい名前に変えたいときは、`Rename-ServerList.bat`をダブルクリックするか、サーバー管理ツールの「名前を推測されにくくする」を押してください。中でファイルを移すだけなので、すぐ終わります。名前を変えると、友人に伝えたアドレスは使えなくなります。確認コードは変わらないので、友人はランチャーの「編集」で配信アドレスを変えるだけで済みます。

名前を推測されにくくしても、守れるのは「中身を見つけられにくくする」ところまでです。書き換えや偽のファイルは、これまでどおり署名と確認コードで防ぎます。

## ふだんの作業

| やりたいこと | やること |
|---|---|
| アドオンを足す・入れ替える | `C:\simutrans-server\pak128.japan`にpakをコピーし、simutransサーバーを再起動してから`Publish-Pakset.bat`をダブルクリックする |
| アドオンを外す | pakを消し、再起動してから`Publish-Pakset.bat`をダブルクリックする（外したアドオンを使っているセーブデータは読めなくなることがある） |
| お知らせを変える | サーバー管理ツールでお知らせを書き換えて「保存して署名」を押す |
| メンテナンス中にする | サーバー管理ツールで「メンテナンス中にする」に印を付けて「保存して署名」を押す |
| 確認コードをもう一度見る | `Manage-SigningKey.bat`をダブルクリックする |
| simutransサーバーを増やす | `Add-Server.bat`をダブルクリックする |

サーバーリストをメモ帳などで手で書き換えたときは、`Manage-SigningKey.bat`の「3. サーバーリストに署名し直す」を実行してください。署名し直さないと、友人のランチャーは書き換えを改ざんとみなして読み込みません。稼働中かどうかはランチャーが実際につないで確かめるので、`status`を`online`や`offline`に書き換える必要はありません。

友人のランチャーは、次に同期するときに、変わったファイルだけを自動で落とします。

## 安全面

8080番でできるのは、ファイルの読み出しだけです。構築ツールは、読み出し（GETとHEAD）以外の要求を断る設定を公開フォルダの`web.config`に入れ、実際に断られることを確かめます。フォルダの中身の一覧表示はオフにしてあり、`web.config`自体もIISは配りません。`publish-settings.json`は公開フォルダの外（この`server-setup`フォルダ）にあります。

ファイルを書き換えられるのは、Windows Serverにログインできる人だけです。リモートデスクトップのパスワードは強くしておいてください。万一、配信フォルダを書き換えられても、サーバーリストの署名が合わなくなるので、友人のランチャーが気づいて止まります。

## 署名と確認コード

友人が知らないexeをうっかり実行してしまわないように、サーバーリストに署名を付けます。署名は「管理者が公開したもの」という印です。難しい操作は要らず、公開するたびに自動で付きます。

仕組みをハンコにたとえると、秘密の鍵は管理者だけが持っているハンコで、VPSの中にだけ置きます。署名はそのハンコで押した印で、`manifest.sig.json`として`manifest.json`の隣に置きます。確認コードは印影の見本です。友人に一度だけ伝え、友人のランチャーに覚えてもらいます。確認コードは秘密ではありません。

友人のランチャーは、サーバーリストを読むたびに、印が見本と同じハンコで押されているかと、押したあとで中身が書き換えられていないかを確かめます。誰かが配信フォルダのpaksetや本体やサーバーリストを書き換えても、ハンコがなければ正しい印は押せません。そのときランチャーは「改ざんのおそれ」と表示して止まります。paksetと本体のファイルは、サーバーリストにSHA256（ファイルの指紋）が書いてあるので、サーバーリストの印だけで全部を守れます。

### 管理者がやること

最初に公開したとき（`Setup-Server.bat`や`Publish-Pakset.bat`を実行したとき）に、鍵が自動で作られ、確認コードが黄色で表示されます。この確認コードを、サーバーリストのアドレスと一緒に、DiscordのDMなどで友人に伝えてください。確認コードは見られても問題ありません。ただし、配信サーバーに置いて伝えるのはやめてください。配信サーバーのファイルを書き換えられたら、確認の意味がなくなります。

続けてバックアップを作るかを聞かれたら、作ってください。できた`signing-key-backup.json`は、自分のPCやUSBメモリなど、VPSの外に保管します。バックアップのパスワードは忘れないようにしてください。

あとは何もしなくてかまいません。`Publish-Pakset.bat`や`Add-Server.bat`で公開するたびに、自動で署名し直します。`manifest.json`を手で書き換えたときだけ、`Manage-SigningKey.bat`の「3. サーバーリストに署名し直す」を実行してください。

### 友人がやること

ランチャーでサーバーリストを追加すると、確認コードの入力を求められます。管理者から聞いたコードを入れて「確認して登録」を押してください。ランチャーは確認コードを表示しないので、必ず管理者から聞く必要があります。simutrans本体が自動で入るのは、確認コードを登録したサーバーリストからだけです。登録しなくても、paksetは同期できます。

### 鍵の置き場所と注意

秘密の鍵は`%LOCALAPPDATA%\InfraLauncherServer\signing-key.dat`にあります。Windowsの機能（DPAPI）で、鍵を作ったWindowsユーザーでしか開けないように暗号化してあります。そのため、ファイルをコピーされても、ほかのPCでは使えません。

同じ理由で、公開の作業はいつも同じWindowsユーザーで行ってください。別のユーザーで公開しようとすると、ツールがそのことを知らせて止まります。

鍵は配信フォルダには置かないので、配信フォルダを書き換えられても鍵は盗まれません。ただし、VPSに管理者としてログインされると、鍵も使われてしまいます。リモートデスクトップのパスワードは強くしてください。

### `Manage-SigningKey.bat`でできること

| 番号 | やること | 使うとき |
|---|---|---|
| 1 | 確認コードをもう一度表示する | 新しい友人に伝えるとき |
| 2 | バックアップを作る | まだ作っていないとき |
| 3 | サーバーリストに署名し直す | サーバーリストを手で書き換えたあと |
| 4 | バックアップから戻す | VPSを作り直したとき（同じ確認コードを使い続けられる） |
| 5 | 鍵を作り直す | 鍵が盗まれたおそれがあるときだけ。確認コードが変わるので、友人全員に新しいコードを伝え、ランチャーの「編集」で入力し直してもらう |

鍵をなくし、バックアップもないときは、5で作り直してください。

## 本体の配布とHTTPS

サーバーと同じsimutrans本体を、友人のPCに自動で入れられます。友人はsimutransを入れていなくても、ランチャーで同期して起動するだけで遊べます。サーバーと同じ本体なので、本体の違いによるチェックサムのずれも起きません。

paksetを公開するときは、paksetフォルダの1つ上にある本体も、部品ごとに公開します。この処理は`Publish-Engine.ps1`が行い、`Add-Server.bat`と`Publish-Pakset.bat`から自動で呼ばれます。

配るexeは次の順で決めます。

1. そのsimutransサーバーのポート（`-server 8634`など）で動いているプロセスのexe
2. `simutrans.exe`、または`simutrans*.exe`や`sim-*.exe`（OTRPの`sim-WinGDI64-OTRPv57_0_1.exe`など）が1つだけなら、そのexe
3. 決められなければ、フォルダ内のexeを新しい順に並べるので、番号で選ぶ（空欄なら本体は配らない）

1の方法なら、サーバーの本体を新しい版に入れ替えたときも、次の公開で自動的に新しい版に切り替わります。配信フォルダの版の名前には、exeの名前を使います。

配るものは許可リスト方式で、部品ごとに決めます。友人はランチャーの「インストール設定」で、「推奨」か「カスタム」を選べます。

| 部品（推奨設定） | 中身 | 扱い |
|---|---|---|
| 本体と設定・スクリプト・テーマ | 選んだ本体のexe、`.dll`、`ai` `config` `font` `scenario` `script` `skin` `text`、`themes`の直下の`.tab`と`.pak` | 必須（友人は外せない） |
| 音楽 | `music` | 推奨 |
| ライセンス・説明書 | `license*.txt` `copyright*.txt` `readme*.txt` | 推奨 |

必須の部品は、友人が外すことはできません。画面の見た目を決める`themes`がないとsimutransは起動しないので、テーマも必須に入れています。`themes`からは、テーマとして使う直下の`.tab`と`.pak`だけを配ります。中にほかのフォルダやセーブデータが混ざっていても配りません。推奨の部品は、友人が「推奨」を選んだときに落とします。必須でも推奨でもない部品は、友人が「カスタム」で選んだときだけ落とします。上の表にないもの（`maps`、`generated-scripts`、`history.txt`など）は配りません。配りたいときは部品に足してください。

設定にかかわらず、絶対に配らないものもあります。`.bat`や`.cmd`や`.ps1`や`.vbs`などのスクリプト、本体以外のexe（Nettool、makeobj、ほかの版）、`.sve`と`.sv_`（セーブデータやパスワード）、`settings.xml`、ログ、`save`と`screenshot`と`addons`のフォルダです。paksetのフォルダも本体には入れませんが、これはpaksetの公開で別に配るためです。友人のPCでは、ランチャーが本体のフォルダの中にpaksetを置くので、サーバーと同じ並びになります。

部品の設定を変えるときは、[engine-files.default.json](engine-files.default.json)を`engine-files.json`という名前でコピーして編集します。部品（`components`）ごとに`folders`と`files`（`*`が使える）、`required`と`recommended`を書き換えてください。`folders`に`themes/*.tab`のように「フォルダ/名前」と書くと、そのフォルダの直下にある名前の合うファイルだけを配ります。`engine-files.json`があれば、ツールはそちらを使います。公開のたびに、部品ごとのファイル数とサイズ、配らなかったフォルダ、絶対に配らないものを表示するので、確かめてください。

本体はファイル一覧方式で`engine\<版>\`に置きます。本体が更新されたときも、友人は変わったファイルだけを落とします。中身が前回と同じなら置き直さず、どのサーバーも使わなくなった古い版は消します。本体はWindows版だけを配ります。MacやLinuxの友人は、手元のsimutransをランチャーの「設定」で指定します。

`config/simuconf.tab`は、友人のPCに一度入れたら上書きしません。友人が自分で設定を変えたり、ランチャーがプレイヤー名を書き込んだりするためです。サーバー側でこのファイルを変えても、すでに入れた友人には届きません。届けたいときは、友人に手元の`config/simuconf.tab`を消してから同期してもらってください。

本体は実行ファイルなので、すり替えられると、友人のPCで好きなプログラムを動かされるおそれがあります。そのためランチャーは、友人が確認コードを登録したサーバーリストからしか本体を入れません。それ以外ではpaksetだけを同期し、本体は手元のものを使います。さらに、ランチャーが入れた本体を初めて起動するときは、友人に確認してもらってから起動します。

HTTPSにするのもおすすめです。書き換えは署名で防げますが、HTTPSにすると通信が暗号化され、もう一段守れます。HTTPSにするには、構築ツールで「HTTPSにしますか？」にYと答えるか、あとから`Enable-Https.bat`をダブルクリックします。

HTTPSの設定では、証明書を取るツール[win-acme](https://www.win-acme.com/)で無料の証明書（Let's Encrypt）を取得し、IISに設定します。win-acmeはGitHubから入れ、公開されているSHA256と電子署名を確かめてから使います。証明書はwin-acmeが自動で更新します（タスクスケジューラに登録されます）。取得と更新のたびに、Let's Encryptが`http://<ドメイン>/`（80番）にアクセスして確認します。そのため、80番は開けたままにしてください。

HTTPSにしたら、友人に`https://<ドメイン>:8443/<サーバーリストの名前>`を伝え、ランチャーの「編集」で配信アドレスを変えてもらいます。確認コードは変わりません。

## Publish-Pakset.ps1の詳細

| 引数 | 説明 |
|---|---|
| `-Source` | サーバーが使っているpaksetフォルダ。省略すると`publish-settings.json`の値 |
| `-Destination` | 公開フォルダの中の、pakset用のフォルダ。省略すると`publish-settings.json`の値 |
| `-Manifest` | 書き換えるサーバーリスト。省略するとファイル一覧だけ作る |
| `-ServerId` | サーバーリストの中で書き換えるサーバーの`id`。同じpaksetを使うサーバーが複数あれば、カンマ区切りで並べる |
| `-Version` | 書き込むpaksetのバージョン。省略すると日時（例: `2026.09.26-2100`） |
| `-IndexUrl` | `index.json`のアドレス。省略すると、サーバーリストから見た相対パスになる（公開フォルダがサーバーリストと同じフォルダかその下にある場合） |

スクリプトは、変わったファイルだけを公開フォルダにコピーし、`-Source`から消えたファイルは公開フォルダからも消します。続けて、各ファイルのパスとサイズとSHA256を書いた`index.json`を作ります。IISで`.pak`や`.tab`、ファイル名に`+`を含むファイルを配信できるように、`web.config`も書きます。自分で作った`web.config`がある場合は触りません。最後に、サーバーリストの`pakset`を`index_url`と`index_sha256`と`version`に書き換え、zip方式の`url`と`sha256`は消します。

実行ファイルなど（`.exe`、`.dll`、`.bat`など）は、警告を出して公開しません。
